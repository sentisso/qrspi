# DELTA

This plugin is HumanLayer's RPI Claude Code plugin with its HumanLayer platform dependencies removed. The upstream skills become phase process files behind one `rpi` orchestrator skill, adapted from HumanLayer's platform-free `skills` repository. This file lists every change from upstream as an ordered action. To take an upstream update, check out the new upstream commit and run all actions again in order.

Scripted actions are copy, render and rename commands. Manual actions are edits a person applies and reviews by hand.

## Upstream

| | |
|---|---|
| Repository | `git@github.com:humanlayer/humanlayer.git` |
| Commit | `f9bd73534a9fb7099a274f951b698b1297122fd9` (2026-11-02) |
| Local checkout | `../resources/humanlayer` |
| Plugin source | `apps/riptide-rpi-claude-plugin/` |
| Agent source | `apps/riptide-daemon/src/agents/claudecode/bundled-agents.ts` and `agents/*.ts` next to it |

The orchestrator design comes from `https://github.com/humanlayer/skills`, local copy in `../resources/humanlayer-skills`, version 1.0.0. Its files are not synced.

## Reapplying

Run from this directory after updating the local checkout and the commit in the table above:

```bash
UP=../resources/humanlayer
```

Then run each scripted action and apply each manual action in order.

## Files Owned by the Port

S1 never overwrites these:

- `.git/`, `DELTA.md`, `NOTICE`, `README.md`
- `scripts/`
- `skills/rpi/scripts/`
- `agents/`, regenerated by S2
- `skills/rpi/references/agents`, a symlink to `../../../agents` for agents without plugin subagents
- `skills/rpi/SKILL.md`, `skills/rpi/references/workflow.md`, `skills/rpi/references/workflow-choice.md`

## Actions

### S1. Copy the plugin into the orchestrator layout (scripted)

Each upstream skill `skills/<step>/` becomes `skills/rpi/references/<step>/`, with `SKILL.md` renamed to `process.md`. The second copy dereferences symlinks because upstream's `show-me.md` files link into another HumanLayer plugin.

```bash
rsync -a --delete \
  --exclude /.git/ --exclude /DELTA.md --exclude /NOTICE --exclude /README.md --exclude /scripts/ --exclude /agents/ --exclude /skills/ \
  "$UP/apps/riptide-rpi-claude-plugin/" ./
mkdir -p skills/rpi/references
rsync -aL --delete --exclude /workflow.md --exclude /workflow-choice.md --exclude /agents \
  "$UP/apps/riptide-rpi-claude-plugin/skills/" skills/rpi/references/
for f in skills/rpi/references/*/SKILL.md; do mv "$f" "${f%SKILL.md}process.md"; done
```

### S2. Render the bundled subagents (scripted)

The HumanLayer daemon injects seven subagents into every session through the Agent SDK, and the upstream plugin ships none. The process files call them as `rpi:<name>`. `scripts/render-agents.ts` imports the daemon's agent registry and writes one `agents/<name>.md` per agent with upstream's own `renderAgentMarkdown`. It drops the `rpi:` prefix because Claude Code adds the plugin name `rpi` as the namespace.

```bash
rm -rf agents && bun scripts/render-agents.ts "$UP" agents
```

The daemon's setting that switches the three `codebase-*` research agents to `haiku` is not rendered. The agents keep their upstream `model` values.

### S3. Rename the artifact root (scripted)

Two daemon agents still use the older `thoughts/tasks/` and `thoughts/shared/plans/` roots. Both become `.rpi/tasks/`.

```bash
grep -rlF '.humanlayer/' skills agents | xargs sed -i 's#\.humanlayer/#.rpi/#g'
grep -rlE 'thoughts/(tasks|shared/plans)/' skills agents | xargs -r sed -i -E 's#thoughts/(tasks|shared/plans)/#.rpi/tasks/#g'
```

### S4. Replace `{SKILLBASE}` with `${CLAUDE_SKILL_DIR}` (scripted)

Upstream `{SKILLBASE}` is the directory of each skill. `${CLAUDE_SKILL_DIR}` is the directory of the `rpi` skill, so every path gains the step's `references/<step>/` prefix.

```bash
for d in skills/rpi/references/*/; do
  step=$(basename "$d")
  grep -rlF '{SKILLBASE}/' "$d" | xargs -r sed -i "s#{SKILLBASE}/#\${CLAUDE_SKILL_DIR}/references/$step/#g"
done
```

Read every changed line when upstream adds a `{SKILLBASE}` reference. A reference that points outside its own step needs a manual fix.

### S5. Share one `show-me.md` (scripted)

Upstream keeps an identical `show-me.md` in three steps. The port keeps one at `skills/rpi/references/show-me.md`. The loop prints the copies that differ. Stop and merge them by hand if it prints anything.

```bash
R=skills/rpi/references
for f in $R/*/references/show-me.md; do cmp -s "$f" $R/create-design-discussion/references/show-me.md || echo "differs: $f"; done
mv $R/create-design-discussion/references/show-me.md $R/show-me.md
rm $R/*/references/show-me.md
grep -rlF '/references/show-me.md' skills | xargs sed -i -E 's#\$\{CLAUDE_SKILL_DIR\}/references/[a-z-]+/references/show-me\.md#${CLAUDE_SKILL_DIR}/references/show-me.md#g'
```

### S6. Rewrite `/rpi:<step>` commands as `/rpi <step> <task-slug>` (scripted)

Upstream hands off to the next skill with `/rpi:<step>`. The port has one `rpi` skill that takes the step and the task slug as arguments.

```bash
grep -rlE '/rpi:[a-z-]+' skills | xargs -r sed -i -E 's#/rpi:([a-z-]+)#/rpi \1 <task-slug>#g'
```

### S7. Rename the `tdd` steps to `tech-design` (scripted)

`create-tdd` and `iterate-tdd` become `create-tech-design` and `iterate-tech-design`, in the step directories and in every reference to them.

```bash
R=skills/rpi/references
for s in create iterate; do mv -T $R/$s-tdd $R/$s-tech-design; done
grep -rlE '\b(create|iterate)-tdd\b' skills | xargs -r sed -i -E 's#\b(create|iterate)-tdd\b#\1-tech-design#g'
```

### C1. Check the paths (scripted)

Check that no `{SKILLBASE}` remains and that every `${CLAUDE_SKILL_DIR}` path exists. Both commands print nothing on success:

```bash
grep -rn 'SKILLBASE' skills
grep -rhoE '\$\{CLAUDE_SKILL_DIR\}/[A-Za-z0-9_./-]*[A-Za-z0-9_]' skills | sort -u | while read -r p; do
  [ -e "skills/rpi/${p#\$\{CLAUDE_SKILL_DIR\}/}" ] || echo "missing: $p"
done
```

### M1. Orchestrator skill (manual)

`skills/rpi/SKILL.md` follows the wording of `skills/rpi/SKILL.md` in the `skills` repository. It keeps that file's step selection, create-or-iterate default, task directory matching and what's-next detection. It replaces what the HumanLayer platform supplies to each session:

- It states the value of `${CLAUDE_SKILL_DIR}`. Claude Code substitutes the variable only in `SKILL.md`, and the process files are read as plain files.
- It maps "the task artifact directory from your system prompt" and the `TASKNAME`/`TASKSLUG` placeholders to the task directory it selects.
- It writes `.rpi/tasks/<task-slug>/ticket.md` from the user's task description when a task starts, in the `# <name>` plus description format of the HumanLayer task form.
- It points agents that can't load the plugin's subagents to their instructions in `references/agents/`.

`skills/rpi/references/workflow.md` holds the flows, the next-step table, the document precedence and the document layout from HumanLayer's skills and workflows reference. `skills/rpi/references/workflow-choice.md` holds the flow chart shown when a new task starts.

Review these files against upstream when an update adds, renames or removes a skill, and against the `skills` repository when it changes.

### M3. Rewrite tool calls as plain instructions (manual)

Upstream writes file reads, commands and writes as Claude Code tool calls, inline and in fenced blocks. Rewrite each one as a plain instruction any agent can follow, in the style of the `skills` repository:

- An inline `` `Read(<path>)` `` becomes `` Read `<path>` `` at the start of a line and `` read `<path>` `` inside a sentence.
- A fenced block of `Bash(<command>)` lines becomes a ` ```bash ` block with the bare commands.
- An inline `` `Bash(<command>)` `` or `Bash(`<command>`)` becomes `` `<command>` ``.
- `Read(<path>)` and `Write(<path>, <content>)` lines in fenced blocks become a sentence that names the files, for example "read `.rpi/workspace.json` and `.rpi/workspace.local.json`". In a block that mixes reads and commands, the reads move into the sentence before a ` ```bash ` block that keeps the commands.

This check prints nothing when the rewrite is complete:

```bash

```

## Port Extensions

These actions go beyond removing HumanLayer. They make the plugin work on any repository hosting service.

### M8. Make repository hosting tool-agnostic (manual)

Upstream drives GitHub through the `gh` CLI. The port names each operation in neutral words and lets the agent find the tooling:

- `describe-pr` step 2 and `create-research` step 8 start with: "Find the tooling available for the repository's hosting service. Check the configured MCP servers and the project setup (remote URL, CLIs on `PATH`, CI config). Examples: `gh` for GitHub, `glab` for GitLab, the Azure DevOps MCP server." `describe-pr` adds: "Use whichever is available and signed in for every pull request and CI operation below." `create-research` leaves out "CI config" and adds: "Without tooling, work from the remote URL."
- `describe-pr`: "If `gh` is missing or signed out, stop and tell the user" becomes a fallback: write and save the description, tell the user which steps to do by hand (create the PR, paste the description, check CI), and skip the CI watch.
- `describe-pr`: each `gh` command becomes the operation it performs: find the PR for the current branch, collect PR metadata and changed files, set the PR description from `{output-path}`, check the PR for merge conflicts, check CI status, read the failed run's logs, rerun the failed jobs once. `mergeable` values become "hasn't computed mergeability yet" and "has conflicts". `gh pr checks --watch --fail-fast` becomes "wait for them and stop waiting at the first failure", using the tooling's watch mode if it has one and otherwise checking every 2 minutes. Plain `git` commands stay.
- `create-research` step 8: `gh repo view` and the `github.com` URL become "Create permalinks to `{file}` at `{commit}` and `{line}` in the hosting service's URL format."
- `create-research` and `iterate-research`: "Link to GitHub" becomes "Link to the hosting service".
- `describe-pr/scripts/inject-walkthrough-diffs.sh`: delete the `--pr` option and its `gh pr diff` branch, keep `git diff`, and shorten the `usage()` line range to the new header. In `pr_walkthrough_example.html`, "`gh pr diff`" becomes "`git diff`".

### M10. Set up worktrees with a script (manual)

Upstream's daemon creates the worktrees and links the task directory into each session's checkout. The port does both in `skills/rpi/scripts/setup_worktree.py`, which follows the merge rules of upstream's `apps/riptide-ui/src/lib/workspace-config.ts` without its defaults. The script requires the `.rpi/workspace.json` that `/rpi configure-workspaces` writes. When the file or one of its required keys is missing, the script stops and tells the agent to send the user to `/rpi configure-workspaces`. Review the script when upstream changes that file.

In `setup-worktree`:

- Delete step 2, which writes a default `.rpi/workspace.json` or one derived from a legacy `create_worktree.sh`.
- Renumber step 3 to 2 and step 4 to 3, along with "don't proceed to step 4" and "an error in Step 3".
- In the new step 2, replace everything from "Create the worktree according to" up to "If there are any error messages" with:

````markdown
Create the worktrees by running the setup script from the repository root:

```bash
python3 ${CLAUDE_SKILL_DIR}/scripts/setup_worktree.py TASKSLUG
```

The script merges `.rpi/workspace.json` with `.rpi/workspace.local.json`, and stops with instructions for the user when the workspace is not configured. For each repo it creates the worktree, copies the `copyGlobs` files and runs the setup command. It links the worktree's `.rpi/tasks` to this checkout's `.rpi/tasks`, so the task documents stay in one place. It prints a `worktree:` line per repo, and its last line `start: <path>` is `[WORKTREE_FULL_PATH]` for the final answer.
````

This check prints nothing when the rewrite is complete:

```bash
grep -nE '<loop for="each repo|git worktree add|create_worktree|index=4' skills/rpi/references/setup-worktree/process.md
```
